## M5-01: Withdrawal safety

- **Findings:** 1 and 2. Spec §7.4, §6.2.
- **Scope:**
  - `api.request_unpublish` refuses an entry that isn't published and has no publish in flight.
  - `worker_commit_unpublish` never links a repeat unpublish to a release: an already-unpublished entry's request ends as `superseded`.
  - Withdrawal checks stop only on the entry's latest committed request (decision 65): a failed or superseded request stops nothing.
  - No path confirms a withdrawal with nothing checked if a delivered release held the entry, including a publish and unpublish coalesced into one build, and a failed release whose pointer was written. Those deliveries stay unconfirmed.
  - The withdrawal state is stored on the delivery before the pointer poll and live window, so a killed run leaves a retried, alertable row.
- **Acceptance:** pgTAP and integration tests reproduce both findings and fail before the fix. A second unpublish from a stale panel shows a plain refusal, with no change to the status. A killed run is retried and alerts. No editor sees "Tekið af vef" without a passed check.

## M5-02: Editor limits

- **Findings:** 3, 4 and 5. Spec §4.3, §4.5, §4.6.
- **Scope:**
  - No exposed view carries `drafts.data` or `revisions.data`, so PostgREST can't filter or bulk-read it. The editor reads one entry's data through by-id `api` functions.
  - Length limits by `CHECK` on `title`, `type`, `default_alt`, `filename` and `slug`-like text, enforced before the audit copy. Values are chosen so all existing staging rows pass.
  - `api.request_unpublish` and other audit-writing calls can't carry unbounded text into `audit_log`.
  - §4.5 and §4.6 are amended to match.
- **Acceptance:** tests show `data` can't be read by list or filtered by regex, and oversized text is refused. Existing editor flows keep working. The persona matrix passes.

## M5-03: Sign-in and sessions

- **Findings:** 7, 8 and 9. Spec §4.4, §8.1.
- **Scope:**
  - Session cookies get `secure`, `sameSite` and a bounded lifetime, and `httpOnly` if the browser client doesn't need to read them.
  - The CMS sends `Content-Security-Policy` with `frame-ancestors`, `X-Content-Type-Options`, `Referrer-Policy` and `Strict-Transport-Security`.
  - `email_change.html` uses the token-hash and POST pattern of the magic link.
  - Auth rate limits (finding 7) are parked by decision 66.
- **Acceptance:** tests pin the cookie flags and headers. An email change needs a POST from each address. Browser tests run by Einar pass.
